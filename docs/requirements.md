### 5.3 문제 관리
- 관리자 대시보드에서 문제 등록/수정/조회

- 초기 MVP에서는 관리자가 수동으로 문제를 입력하는 방식으로 구현
- 추후 PDF 반자동 초안 생성 기능 고도화 가능성 검토

### 5.4 시험 관리
- 시험 생성
- 시험 유형 설정 (Level Test / Mock Test / Word Test)
- 시험 버전 관리
- 시험에 문제 연결
- 학생별 시험 배정
- 시험 활성/비활성 관리
- Level Test 및 Mock Test는 SAT Reading & Writing 적응형 구조를 따른다
- 시험 생성 시 Module별 문항 구성을 관리할 수 있어야 한다
  - Module 1: Reading 13문항 + Writing 14문항
  - Module 2: Reading 15~16문항 + Writing 12~11문항
- Module 2의 문제 구성은 Upper / Lower 분기 정책 및 시험 버전에 따라 관리 가능하도록 설계한다
- 시험 생성 시 관리자 화면에서 Module별 목표 문항 수와 문제 배치를 검증할 수 있어야 한다
- 시험 저장 시 Module별 Reading / Writing 문항 수가 정책과 맞지 않으면 저장되지 않도록 검증한다

### 5.5 시험 응시
- 레벨 테스트 및 모의고사는 Module 1, Module 2 각각 32분 제한시간이 있다
- Level Test 및 Mock Test의 문항 구성은 다음과 같다
  - Module 1: Reading 13문항 + Writing 14문항
  - Module 2: Reading 15~16문항 + Writing 12~11문항
- 시간 내에 Module 1을 제출하면 Module 2로 넘어간다
- Module 1 결과에 따라 Module 2는 Upper 또는 Lower 트랙으로 분기될 수 있다
- 각 Module은 제한시간이 종료되면 자동 제출된다
- 주요 시험 응시 화면은 태블릿 환경을 고려해 반응형으로 설계한다
- 답안 선택 및 문제 이동은 터치 환경에서도 불편하지 않도록 구성한다

### 5.6 채점 및 결과표
- 채점:
 - Module 1 정답 개수 계산
 - M1 >= 19면 Upper, 아니면 Lower(최대 630)
 - Module 2 정답 개수 계산
 - total = M1 + M2
 - 분기 유형이 Upper면 Upper 테이블 조회, Lower면 Lower 테이블 조회
 - 최종 점수 반환
 - 각 유형별로 (맞은 개수/전체 문항 수) 기준으로 계산해서 표시하고 문항별 정답률(60%, 70% 등)은 초기에는 별도 값 없이 진행하고, 이후 실제 테스트 데이터가 쌓이면 그 데이터를 기반으로 계산하여 고도화하는 방향으로 구현
- 결과표: 유형 분류(CAS, IAI, SEC, EOI / VOC, PUR 등)는 문제 등록 시 설정하는 방식으로 진행할 예정
- 결과표는 학생/학부모, 강사, 운영/부원장 admin, super_admin이 권한 범위 내에서 조회할 수 있다

## 6. 시험 정책

### 6.1 공통
- 시험은 Reading & Writing(RW)만 포함
- Module 1, Module 2 구조
- 각 Module당 32분 제한시간
- Level Test 및 Mock Test의 기본 문항 구성은 다음과 같다
  - Module 1: Reading 13문항 + Writing 14문항
  - Module 2: Reading 15~16문항 + Writing 12~11문항
- Module 2는 Module 1 결과에 따라 Upper / Lower 트랙으로 분기될 수 있다
- 시험 중 네트워크 단절 시 마지막 저장 상태를 기준으로 시험 재개 가능
- 답안은 실시간 또는 일정 주기로 저장하여 재접속 시 응시 상태를 복구할 수 있어야 한다

### 6.2 Level Test
- 학원에서 지정한 시험 1개 사용
- 시험은 버전 관리 가능 (Level Test v1, v2 등)
- Level Test는 SAT Reading & Writing 적응형 구조를 따른다
  - Module 1: Reading 13문항 + Writing 14문항
  - Module 2: Reading 15~16문항 + Writing 12~11문항
- 기존 응시 기록은 유지
- 기본은 진단 목적의 시험이지만, 네트워크 문제 또는 운영 필요 시 재응시 가능

### 6.3 Mock Test
- 강사가 학생에게 시험을 배정하는 구조
- 학생은 본인에게 배정된 시험만 응시 가능
- Mock Test는 SAT Reading & Writing 적응형 구조를 따른다
  - Module 1: Reading 13문항 + Writing 14문항
  - Module 2: Reading 15~16문항 + Writing 12~11문항
- 여러 시험 반복 응시 가능
- 수업 운영상 주기적으로 새로운 시험이 추가될 수 있음
- 운영 정책상 반복 응시 가능
- 네트워크 문제 또는 운영 필요 시 재응시 가능

### 6.4 Word Test
- 보류 사유: 1차 MVP가 28일까지라 급한 불부터 끄기
- 추후 개발 예정 내용:
  1) 주관식
  2) 타이머: 추후 물어볼 예정
  3) 재응시 정책: 추후 확정

## 7. 채점 정책

### 7.1 Raw Score
- 각 Module별 정답 개수 계산
- Module 1은 Reading 13문항 + Writing 14문항 기준으로 구성된다
- Module 2는 Reading 15~16문항 + Writing 12~11문항 기준으로 구성된다
- total = Module1 + Module2 정답 개수

### 7.2 Track 분기
- Module1 정답 개수 기준
- 19개 이상: Upper
- 18개 이하: Lower

### 7.3 Scaled Score
- score_table 기반 점수 환산
- Upper: 최대 800
- Lower: 최대 630
- 시험 버전별 환산표 적용 가능

## 8. 개인정보/보안 정책

- 비밀번호는 평문 저장 금지, 해시(BCrypt)로 저장
- 관리자도 기존 비밀번호 조회 불가
- 비밀번호는 초기화 방식으로만 처리
- 강사 계정은 학생 개인정보(전화번호, 카카오톡, 로그인 ID) 조회 불가
- 민감정보는 백엔드에서 필드 단위로 차단 (DTO 분리)
- 인증은 JWT 기반으로 처리
- 비밀번호 초기화 권한은 super_admin 및 운영/부원장 admin만 가진다
- 강사 admin은 비밀번호 초기화 권한이 없다
